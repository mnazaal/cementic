B — Blocking / destructive

B1. CI is red on main before any test runs measured
uv.lock:53,87 · .github/workflows/ci.yml:24,50,70

All three CI jobs install with uv sync --locked --extra dev, which fails when the lock does not match pyproject.toml. uv.lock still lists pgvector>=0.2.0 as a cementic dependency; CHANGELOG.md:100 records it as removed.

$ uv lock --check

Consequence for the record: PLAN.md's "610 unit + 102 integration passing" describes local runs. CI has never been green on this state.

B2. cementic stop --help recommends a command that deletes the index measured
src/cementic/templates/postgres/compose.yml (all 29 lines) · cli.py:1076 · README.md:129 · templates/postgres/README.md:116

The compose.yml that cementic init postgres writes has no volumes: key and no volume mount. Postgres's whole data directory lives in the container's writable layer. Three places tell the user to run docker compose down — including cementic stop --help, directly after "Postgres is not managed by cementic". That removes the container and every document, chunk, embedding and revision with it.

The Quadlet template gets it right: quadlet/cementic-postgres.container:71 mounts cementic-postgres-data:/var/lib/postgresql, with a comment explaining why the volume must cover the parent dir. The Compose path — the one README tells beta users to take — simply lacks it.

Fix: add the same named volume to both compose.yml files; stop saying down where stop is meant.

C1 — Wrong results, silently

C1.1 Long search queries are silently truncated measured
search.py:28 (MAX_QUERY_CHARS = 8000) vs config.py llama_cpp.n_ctx = 512

8000 chars is ~1100+ tokens; the context window is 512. Two 7540-char queries, identical for the first ~1100 tokens and differing only in their final words, returned bit-identical scores:

HEAD=$(python -c "print('vector database design and retrieval augmented generation '*130, end='')")
cementic search "$HEAD quantum chromodynamics lattice gauge theory"   -c test -n 3 --json
cementic search "$HEAD baroque counterpoint fugue harpsichord"        -c test -n 3 --json
# both returned the same 3 hits with identical scores, to 6 dp:
#   0.439757 / 0.435583 / 0.434400   (same source_path in the same order)

The tail is discarded, exit 0, no warning. scripts/measure_chunk_context_fit.py guards the document path; nothing guards the query path.

Fix: bound the query in tokens against the profile's n_ctx and raise an error naming the limit.

C1.2 Search SQL omits the freshness conditions revisions.py calls "the single definition of what counts"
search.py:155-170

The hand-written SQL filters on profile ids only. The scope builders additionally require ed.status='done', cd.status='done', ed.source_file_hash = sd.file_hash, cd.source_content_hash = ed.content_hash. pipeline_worker.py and status_service.py use them; grep shows search.py references none.

Symptom: a watched file changes and re-extraction fails → search keeps serving the old content of that file forever, ranked normally, with no indication it is stale.

Fix: reuse extracted_scope/chunked_scope rather than hand-writing the predicates a third time.

C1.3 hnsw_ef_search default 40 < MAX_SEARCH_RESULTS 50
config.py:331 · search.py:27,142

cementic search -n 50 can return ≤40 rows. Worse: every filter (sd.collection, sd.status, profile ids) is on joined tables, so it is a post-filter against a vector table shared by all collections on that model, and hnsw.iterative_scan appears nowhere in the repo. A small collection can return few or zero hits while matches exist. Intermittent — depends on the planner choosing the index scan.

Fix: SET LOCAL hnsw.iterative_scan = relaxed_order, and pass max(config.index.hnsw_ef_search, top_k).

C1.4 Chunk text is corrupted at token boundaries measured
chunk.py:54

encoding.decode() uses tiktoken's default errors="replace", so a boundary inside a multi-byte character emits U+FFFD. At production settings (512/128):

from cementic.chunk import chunk_text
# emoji      : 10 chunks,  7 contain U+FFFD
# devanagari : 15 chunks,  8 contain U+FFFD
# cjk        :  8 chunks,  0 contain U+FFFD

That corruption is what lands in chunks_v2.content and what cementic search prints.

Fix: decode via decode_bytes and carry incomplete trailing bytes into the next chunk.

C2.4 cementic status can block 120s and then return an answer it already had
status_service.py:396 → embedding_runtime.py:312-327; overridden at status_service.py:408-410

Consolidation worth doing

  • Three implementations of "busy vs dead" — client_is_healthy_or_busy, check_health's inline fallback, doctor._daemon_state — with three different probes and timeouts (120s poll / instant pid check / 2s HTTP). This is why the three commands disagree about what "healthy" means.
  • Two full implementations of the same six counts — status_service.load_pipeline_status_bulk and pipeline_worker._compute_revision_counts. They agree only because both consume the revisions.py scope builders; a comment records that they previously drifted.
  • ~70 duplicated lines between the two workers (_setup_logging/_fatal/_handle_shutdown/stop, including identical docstrings). That duplication is why C2.5's fix must be applied twice and why the state_manager placement bug (M table) exists in one worker and not the other.

Packaging

Correct: console-script entry point; wheel and sdist both build cleanly and contain all 5 template files including the force-included .env; cementic init postgres works from an installed tree. No packaging bug there.

  • Undeclared but directly imported: click (cli.py:15 — and cli.py:78-114 subclasses click.HelpFormatter/click.Context) and pymupdf (extract.py:11,16,51). pyproject.toml:31-34 already documents that a typer bump breaks exactly these subclasses, yet click has no constraint at all. Verified correct (worth not re-checking)

  • No path traversal in storage.py; both symlink escape routes are covered.

  • The embed lease is honest — every exit path writes a terminal status or releases the claim; requeue_interrupted_artifacts mops up after SIGKILL. Cascade coverage is real.
  • filelock.py is correct, including non-inheritance of the fd into detached children.
