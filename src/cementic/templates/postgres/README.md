# cementic Postgres setup

This directory contains a local Postgres service for cementic with `pgvector`
and `pgvectorscale`. It is generated by `cementic init postgres DIR`.

## One-time start

Docker:

```bash
docker compose up -d
docker compose ps
docker compose logs postgres
```

Podman:

```bash
podman compose up -d
podman compose ps
podman compose logs postgres
```

You do not need to run Compose every time you use cementic. The Compose service
uses `restart: unless-stopped`, so it is intended to stay available as a local
persistent database service.

After it starts, check cementic readiness:

```bash
cementic status --doctor
```

Then use cementic normally:

```bash
cementic start ~/docs -c research
cementic search "your query" -c research
```

## Defaults

The `.env` file matches cementic's built-in database defaults:

```text
CEMENTIC_DB_USER=cementic
CEMENTIC_DB_PASSWORD=cementic
CEMENTIC_DB_NAME=cementic
CEMENTIC_DB_PORT=5432
```

If you change these values, set the matching `CEMENTIC_DB_*` environment
variables before running cementic, or put the equivalent values in your cementic
config file.

## Optional Podman Quadlet service

The `quadlet/cementic-postgres.container` file is an optional user-systemd setup
for Podman, so you don't have to start/stop the container by hand.

This unit requires an environment file to exist (even empty) before its first
start -- Podman's Quadlet `EnvironmentFile=` directive does not support an
optional/missing path the way systemd's own directive does:

```bash
mkdir -p ~/.config/cementic
touch ~/.config/cementic/postgres.env
```

To override credentials/db name, put them in that file instead:

```bash
cat > ~/.config/cementic/postgres.env <<'EOF'
POSTGRES_USER=cementic
POSTGRES_PASSWORD=change-me
POSTGRES_DB=cementic
EOF
chmod 600 ~/.config/cementic/postgres.env
```

Then install and start it (build the image first with `podman compose build`
if you haven't already run `podman compose up -d` in this directory):

```bash
mkdir -p ~/.config/containers/systemd
cp quadlet/cementic-postgres.container ~/.config/containers/systemd/
systemctl --user daemon-reload
systemctl --user start cementic-postgres.service
systemctl --user status cementic-postgres.service
```

Do not run `systemctl --user enable` on this unit -- Quadlet-generated units
are transient/generated, and `enable` fails with "Unit ... is transient or
generated". The `[Install]` section in the unit file is processed by Quadlet
itself at `daemon-reload` time, so it's already wired to start at the next
login; no separate enable step is needed.

For services that should survive logout/reboot, also run:

```bash
loginctl enable-linger "$USER"
```

## Upgrading a setup generated before named volumes

Earlier generated setups had no `volumes:` entry, so the database lived in the
container's own writable layer. Recreating the container against this file
starts from a **fresh, empty** named volume — the old data stays in the discarded
layer and your index looks empty.

If you are regenerating over an existing setup, copy the data across before
recreating, with the container still running:

```bash
docker compose stop
docker cp cementic-postgres:/var/lib/postgresql - > pgdata.tar
# or: podman cp cementic-postgres:/var/lib/postgresql - > pgdata.tar
```

Keep that archive until `cementic status` reports your collections again. If you
would rather rebuild than migrate, `cementic start` will re-index from source.

## Stop or remove

Stop the service but keep data/image:

```bash
docker compose stop
# or: podman compose stop
```

Remove the Compose container/network (your indexed data lives in the
`cementic-postgres-data` named volume and survives this):

```bash
docker compose down
# or: podman compose down
```

To delete the indexed data as well — every document, chunk and embedding, with
no undo — add `-v`/`--volumes`:

```bash
docker compose down -v
# or: podman compose down -v
```

## Troubleshooting

- Port conflict: edit `CEMENTIC_DB_PORT` in `.env`, restart Compose, and set the
  same `CEMENTIC_DB_PORT` for cementic.
- Database unreachable: run `docker compose ps` / `podman compose ps`, inspect
  `docker compose logs postgres` / `podman compose logs postgres`, then rerun
  `cementic status --doctor`.
- Extension unavailable: rebuild the image with `docker compose build --no-cache`
  or `podman compose build --no-cache`.
- Changed `.env`: recreate the container with `docker compose up -d --force-recreate`
  or `podman compose up -d --force-recreate`.
